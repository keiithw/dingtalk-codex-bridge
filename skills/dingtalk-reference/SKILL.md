# 钉钉联动参考

本目录只保存脱敏后的流程摘要。真实群会话 ID、用户 ID、机器人 ID、Client Secret、Access Token、Webhook、Cookie 和会话内容必须从本机当前配置或当次工具查询获得，禁止写入仓库。

## 1. 钉钉操作

对应本机 Skill：`dingtalk-operations`。

- 查群时按群名称搜索，区分同名群，记录当前返回的群会话标识。
- 查成员或机器人时核实当前返回的 `openDingTalkId`，不要把 `openBotId`、`robotCode`、普通 `userId` 或显示名混用。
- 发送群消息、@成员、私聊机器人和读取回复时，记录会话 ID、消息 ID、时间和投递状态。
- `delivered` 或接口成功只证明发送接口接受，不证明对方收到、已读或业务处理成功。
- 线上数据查询要区分问题 AI 助手和审批式数据查询机器人，分别记录发起、审批、执行和结果收到状态。

## 2. CODING MR

对应本机 Skill：`coding-auto-mr`。

- 先检查当前仓库、分支、远端和现有 MR，再决定复用或创建。
- push 成功、MR 创建成功、AI 审查完成、合入目标分支和 Jenkins 终态分别核实。
- MR 审查提醒需要当前群会话标识、审查机器人当前身份、MR 链接或编号、推送 SHA 和有效监听窗口。
- 群交接消息只使用用户明确授权的内容。负责人身份必须通过当前群成员结果核实。
- 未取得当前群、机器人、负责人或 SHA 时，不猜测，先列出缺失项并请求补充或执行只读核实。

## 3. DWS 工作日志

对应本机 Skill：`dws-work-report`。

- 生成日报前明确时间范围、仓库范围、Git 作者、模板和收件人。
- 预览和提交分开处理。用户只要求预览时不提交。
- 提交后记录模板、收件人、提交结果和 `reportId`，并回查提交结果。
- 收件人和模板 ID 必须以当前查询结果为准，仓库中只保留占位符。

## 4. 钉钉 Markdown 输出

对应本机 Skill：`dingtalk-output-format`。

- 使用标题、加粗、列表和可复制代码块组织桥接回复。
- 代码块优先使用项目约定的波浪线围栏，避免三反引号在本地桥接中被转换为引用文本。
- 代码修改回复保留文件路径、行号和必要的 diff 上下文。
- 排版规则不改变发送权限，发送仍需当前任务授权。

## 缺失信息处理

按任务判断缺失项。常见缺口包括目标群、目标成员、机器人身份、MR 链接、提交 SHA、DWS 模板、日报收件人、时间范围和发送授权。

1. 先完成不依赖缺失信息的本地只读检查。
2. 能通过当前连接查询的身份和模板，优先重新查询，不复用过期记录。
3. 无法查询且会影响目标或发送的字段，向用户一次性列出缺失项和用途。
4. 未补齐前不发送、不创建错误 MR、不把推测值写入配置或文档。
