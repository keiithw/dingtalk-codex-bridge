# 桥接小农场：钉钉 × Codex

通过钉钉应用机器人与本机 Codex 对话。本项目为 **Windows 原型**：克隆后请跟随下面的步骤初始化；还不是双击即可完成的安装包。

## 让 Codex 帮你安装

用 Codex 打开克隆后的项目目录，发送：

> 请阅读 README，帮助我逐步配置钉钉桥接。先检查 Node.js 和 Codex，然后询问我要授权的工作目录，运行初始化脚本，打开本地控制台，引导我在机器人配置中输入 Client ID 和 Secret、测试并保存。不要让我把 Secret 发到聊天中。完成后帮助我配对和验证一条消息。

Codex 应当解释每步的结果和权限范围；获取凭证和首次配对需由机器人使用者本人完成。不要把真实凭证放进仓库、聊天、截图或命令行。

## 先了解迁移边界

- 每位使用者需要自己的钉钉应用机器人、Codex 登录和本机配置。不要复制原机器人的密钥、配对关系、群登记、聊天记录或 Codex 凭证。
- 配置和状态默认位于当前用户的 `%LOCALAPPDATA%\DingTalkCodexBridge`，不得将其中的内容提交或分享；计划任务名称仍固定。
- 机器人和 Codex 运行在这台电脑；关机、休眠或当前用户未登录时无法处理消息。程序登录自启需要单独创建计划任务。

## 1. 准备环境

1. Windows 电脑、可访问钉钉和 Codex 的网络。
2. Node.js 和 npm：在 PowerShell 中运行 `node --version`、`npm --version`。开发时使用 Node.js 24；其他版本尚未验证。
3. 安装并登录 Codex CLI：执行 `codex --version`、`codex login status`、`codex app-server --help`。登录或版本报错应先解决，登录方式和可用权限以该使用者的环境为准。
4. 打开 [钉钉开放平台](https://open.dingtalk.com/)，进入开发者后台创建**企业内部应用**，在应用能力中添加机器人；选择 **Stream** 接收模式，配置机器人名称、可见范围并发布。Client ID（AppKey）和 Client Secret（AppSecret）可在应用的凭证与基础信息中查看，具体菜单名称以钉钉页面为准；没有创建或发布权限时联系企业管理员。

## 2. 复制程序并安装依赖

克隆仓库后，在项目目录运行初始化脚本（将工作目录替换成你授权的实际目录）。脚本检查环境、执行 `npm ci`、生成个人配置和配对码；若已存在配置则停止，不覆盖：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Workspace "D:\你的项目目录"
```

如果找不到 `codex.exe`，可按脚本提示增加 `-CodexExe "完整路径\codex.exe"`。安装需要访问 npm 包源；`npm ci` 会清除项目中的 `node_modules` 并按锁文件重装。Windows 快捷方式需在本机生成，仓库不包含别人的快捷方式。

## 3. 配置个人凭证和工作目录

初始化脚本已创建个人配置。双击 `scripts\open-console.cmd`，点击 **机器人配置**，在弹框中输入自己的 Client ID 和 Client Secret，点击“测试连接”后“保存”。测试只验证钉钉凭证，实际收发需在后续步骤验证。

配置文件格式供排障参考，不应将真实值写入项目：

```json
{
  "clientId": "钉钉应用的Client ID",
  "clientSecret": "钉钉应用的Client Secret",
  "pairCode": "自己生成的随机配对码",
  "codexExe": "C:\\你的路径\\codex.exe",
  "cwd": "C:\\你的项目目录"
}
```

`codexExe` 必须是当前电脑可执行的 Codex 路径，可用 `where.exe codex` 查找；请确认所选文件能运行 `app-server`。`cwd` 必须存在，并选择允许 Codex 操作的目录。确保仅当前 Windows 用户可以读取配置文件；不要通过命令行参数、日志或截图暴露 Secret。

当前使用 `workspace-write`、网络访问和 `approvalPolicy: 'never'`。额外可写目录通过个人配置的 `writableRoots` 控制，初始化时为空；工作目录本身可写。务必只选择授权的工作目录，并了解该模式不会把审批请求转到钉钉。

当前配对码是配置中的固定值，尚未实现一次性失效。请生成足够随机的配对码，私下完成配对；初次配对前不要把机器人开放给不可信用户。

## 4. 先在前台启动并测试

从程序目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-foreground.ps1
```

1. 看到 Codex 初始化和钉钉连接成功的提示后，在钉钉**私聊自己的机器人**发送 `配对 你的配对码`。
2. 收到配对成功后发送 `你好，只回复：连接正常`。确认能收到最终回复，而不仅是“已接收”。
3. 再发送一个追问，确认多轮对话；测试图片、引用和发群消息时要分别验证，不能只凭连接成功判断可用。
4. 前台测试结束按 `Ctrl+C` 停止。配对和会话状态由程序写在配置文件同目录的 `bridge-state.json`；该文件含用户和群标识，不能与他人共用。

如果失败，先核对机器人是否发布且选择 Stream、当前账号是否在可用范围、Codex 是否登录、工作目录是否存在。进程启动成功不等于钉钉消息已收发。程序日志不要复制密钥、会话回复地址或图片下载地址。

## 5. 配置管理控制台与登录自启

- 双击 `scripts\open-console.cmd` 可启动本机网页。该按钮要求 `node` 在 PATH；控制台仅绑定 `127.0.0.1`，页面关闭后空闲约 10 分钟退出。
- 新安装的控制台读取 `%LOCALAPPDATA%\DingTalkCodexBridge` 下的配置和状态；如配置了 `BRIDGE_CONFIG` 环境变量，控制台使用该文件及其所在目录。前台启动脚本也需要用 `-Config` 指定同一配置文件。
- `scripts\start.cmd`、`restart.cmd`、`stop.cmd` 和控制台重启按钮都依赖名称为 `CodexDingTalkBridge` 的 Windows 计划任务。新电脑需要在“任务计划程序”中为**当前用户登录**创建该任务，操作程序设为本机 `node.exe`，参数为**桥接程序绝对路径**及**个人配置文件绝对路径**；包含空格的参数分别加双引号。先手动运行计划任务并确认实际收发，再启用登录触发器。
- 计划任务可设置失败后重启，并取消不适用的电池限制；任务运行身份必须能读取个人配置、Codex 登录和工作目录。电脑重启后需要对应用户登录才能触发。
- 根目录的 `.lnk` 和 `.ico` 是本机入口和图标；复制到新电脑后需重新创建快捷方式，目标指向 `scripts` 目录中的相应 `.cmd`。脚本本身不会安装计划任务。

## 日常使用与限制

- 私聊 `/new` 清除当前会话关联，下次消息创建新的 Codex 会话；旧会话的恢复依赖本机 Codex 状态和登录。
- 群里 @机器人发送 `登记本群`，然后私聊 `往完整群名发：消息内容`。群消息发送和成员查询需要钉钉接口、权限及群类型支持；名称重复时不会自动选群。
- 控制台的 `@机器人消息` 保存个人配置目录的 `robot-mentions-groups.json` 中获准群聊发给机器人的最近 100 条消息及能下载的图片；新登记群不会自动加入归档。记录保存在个人配置目录的 `robot-mentions`。可私聊 Codex 请求查询；未送达机器人的群消息、启用前的历史和图片下载失败的内容不会自动补齐。
- 图片输入代码支持图片和图文中的下载码，最多 5 张、单张 10 MB；实际类型、权限与模型支持需要实测。引用文字在钉钉提供可读原文时可附带；无法读取时不会自动还原。不要推断图片输出或群历史消息读取已经支持。
- 控制台显示近期动作和状态，不记录消息正文；状态快照最多保留最近 100 条，进程重启后记录重新开始。已有历史日志可能包含临时地址，请自行检查和清理；迁移包不应包含日志。
- 一次只运行一个桥接实例；手动前台测试与计划任务运行时不要同时启动，否则可能产生重复连接。结束任务会中断正在执行的工作。

## 私聊 /relay

先在已配对的私聊打开一个 Codex 会话，再输入：

```text
/relay jenkins <带构建号的完整 URL> [分钟]
/relay mr <CODING MR 链接> <负责人发送人ID> [分钟] | <已登记群完整名称>
/relay status [任务ID]
/relay cancel <任务ID>
```

- 默认等待 30 分钟，可设为 1 至 120 分钟。任务写入配置同目录的 `bridge-relay.json`；重启后到期时间不延长。钉钉私聊回复地址到期或重启后不可用时，以 `/relay status` 为准。结果也会带入原 Codex 会话的下一次消息，不主动启动模型回合。
- Jenkins 需在本机桥接配置中设置 `relayJenkinsBaseUrl`。只对该地址下的指定构建读取 `api/json`，不跟随重定向、不借用登录态、不触发构建。接口要求认证或无法返回结果时，任务到期，不判定为构建失败。Jenkins 终态不是部署或健康检查的证明。
- MR 只接收 `robot-mentions-groups.json` 内已登记群 **实际送达本机器人** 的新消息。负责人需在群里 @本机器人，并发送 `已合并 <完整 MR 链接>`；机器人回调的 `senderStaffId`（缺失时 `senderId`）须与登记一致。只标记为回查信号，不检查历史消息、不接表情、不自动核实或合并 MR。
